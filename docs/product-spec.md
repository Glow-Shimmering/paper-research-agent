# PRAgent Web V1 产品设计文档

> 文档状态：目标设计，尚未全部实现
>
> 原型基线：`prototypes/agent-research-v1` V1.3
>
> 适用分支：`codex/web-v1`
>
> V0 归档：`codex/ownership-plan` 分支与 `v0` 标签

## 1. 产品定义

PRAgent 是一个本地优先、证据驱动的论文研究 Agent。用户不需要先理解“来源、任务、精读卡、比较矩阵”等内部模块，只需在项目对话中描述研究目标，Agent 就负责组织从论文发现到研究成果沉淀的完整过程。

Web V1 的默认主流程是：

`选择项目工作区 → 在默认对话中描述目标 → 确认计划 → 筛选论文 → 精读与比较 → 形成综述 → 完成并沉淀项目公共记忆`

### 1.1 核心价值

1. 把零散的检索、阅读、比较和写作能力组织成一条可恢复的研究过程。
2. 所有重要结论都能回到论文原文证据，不把模型生成内容伪装成事实。
3. 论文在全局共享库中只保存一份，项目研究成果保存在各自工作区。
4. 一个项目支持多个对话，并通过用户确认的 Markdown 成果共享长期上下文。
5. 用户可以随时追问或修改当前及历史阶段，而不是被固定向导锁死。

### 1.2 V1 成功标准

- 新用户能在 2 分钟内选择工作区、创建项目并发出第一个研究目标。
- 用户无需手动创建或命名第一个对话；首次提问后自动得到可修改标题。
- 用户在任一阶段都能询问当前及此前阶段的依据，并通过对话修改产物。
- 完成研究时不需要理解导出和记忆配置；点击“完成”即可自动沉淀成果。
- 新对话能够使用同一项目的公共记忆继续深入研究，同时保持独立消息历史。

## 2. 用户与主要场景

### 2.1 目标用户

主要用户是需要持续阅读、比较和组织学术论文的个人研究者，包括研究生、工程研究人员和需要快速进入陌生主题的开发者。

V1 优先服务个人、本地、单用户工作流，不以团队协作或公开知识库为前提。

### 2.2 核心任务

| 任务 | 用户输入 | 主要交付 |
| --- | --- | --- |
| 主题调研到综述 | 一个研究问题和范围偏好 | 带证据的 Markdown 综述 |
| 单篇论文精读 | 论文、链接或题录 | 结构化精读与证据问答 |
| 论文发现与筛选 | 主题、年份和筛选标准 | 去重候选清单与推荐理由 |
| 多论文比较 | 论文集合和比较目标 | 可扩展比较矩阵、共识与冲突 |
| 基于既有成果深入研究 | 项目公共记忆和新问题 | 新对话、新证据与增量成果 |

## 3. 产品心智模型

### 3.1 对象层级

```text
PRAgent
├─ 全局共享论文库
└─ 项目
   ├─ 项目工作区
   ├─ 项目公共记忆（一个或多个 Markdown 文件）
   └─ 对话
      ├─ 研究目标与计划
      ├─ 阶段记录和版本
      ├─ 入选论文集合
      └─ 精读、比较、综述等产物
```

### 3.2 核心对象

| 对象 | 用户如何理解 | 生命周期与边界 |
| --- | --- | --- |
| 全局共享论文库 | Agent 已掌握的所有本地论文 | Agent 级配置；所有项目可读，并可补充去重后的新论文 |
| 项目 | 一项长期研究主题或工作目标 | 创建时选择独立工作区；包含多个对话和项目公共记忆 |
| 对话 | 一次连续的研究思路或任务 | 项目创建时自动产生默认对话；后续可创建多个独立对话 |
| 研究阶段 | Agent 为完成当前对话组织的过程 | 可回看、追问、修改和重新生成，不等同于不可逆向导步骤 |
| 公共记忆 | 项目内多个对话共同认可的研究成果 | 由“完成”动作生成或更新；“公共”仅指项目内共享，不会公开到网络 |

## 4. 存储与访问边界

### 4.1 全局共享论文库

PRAgent 必须配置一个全局论文库文件夹。所有下载的论文 PDF 都只存放在这个目录中，不因项目不同而复制多份。

每个项目在研究过程中都可以：

1. 检索和访问论文库中的全部论文。
2. 将论文库已有论文加入当前对话的候选或入选集合。
3. 联网发现论文，并在用户授权后向论文库补充缺失文件。
4. 复用已有全文、分块、索引和引用元数据。
5. 查看某篇论文是“论文库已有”还是“需要下载”。

下载前按以下稳定身份顺序去重：

`DOI → arXiv ID → 规范化来源 URL → 文件 SHA-256`

命中已有身份时必须复用现有论文记录与文件，不重复下载。元数据不完整但文件哈希一致时，也必须合并为同一论文。

“项目可访问全部论文”是指 Agent 可以对共享论文库执行题录筛选、全文检索和语义检索，并把与当前问题相关的片段带入对话；不代表把整个论文库一次性发送给模型。研究产物使用的论文集合仍需在当前对话中明确确认和冻结。

### 4.2 项目工作区

创建项目时必须选择一个本地文件夹作为项目工作区。该目录保存：

- 当前项目的中间文件与可恢复任务状态；
- 精读、比较、综述等输出；
- 项目公共记忆 Markdown；
- 与当前项目有关的导出文件和用户编辑结果。

项目工作区不复制论文 PDF。其他项目的对话、公共记忆和研究产物不能自动进入当前项目上下文。

### 4.3 项目公共记忆

每次对话完成后生成一个 Markdown 成果文件，并加入项目公共记忆。多个已完成对话可以形成多个公共记忆文件，不用相互覆盖。

公共记忆至少包含研究目标、研究范围、入选论文、关键结论、原文证据引用、比较结果、证据不足项和后续研究建议。

新对话默认可以检索项目全部公共记忆。用户修改公共记忆后，后续对话读取最新版本；已有对话保留其当时使用的版本记录。

公共记忆应建立可检索索引。对话只取回与当前问题相关的 Markdown 段落，并标明来源文件和版本，不把历史记忆全文无差别塞入模型上下文。

## 5. 信息架构

### 5.1 全局侧栏

侧栏承担上下文切换，不展示内部功能模块菜单：

1. 当前项目与项目切换入口。
2. “新建对话”按钮。
3. 当前项目的对话列表及手动重命名入口。
4. 项目公共记忆入口。
5. 全局模型、共享论文库和数据设置入口。

### 5.2 主工作区

主工作区采用“对话 + 成果工作区”并列结构：

| 区域 | 职责 |
| --- | --- |
| 左侧对话 | 描述目标、补充条件、追问依据、修改产物、确认关键操作 |
| 右侧成果工作区 | 展示计划、论文、执行进度、精读、比较和综述等结构化结果 |
| 顶部阶段导航 | 显示当前研究进度，并允许回看已到达阶段 |
| 运行详情 | 展示任务状态、失败原因、恢复和取消，不作为普通用户的主入口 |

## 6. 项目与对话生命周期

### 6.1 首次设置

首次使用时，用户先选择全局共享论文库文件夹，再创建第一个项目。后续新建项目直接复用该论文库配置，除非用户在全局设置中修改。

### 6.2 创建项目

用户只需要提供项目名称和项目工作区。创建成功后系统自动进入该项目的默认对话，不再要求单独创建对话。

项目创建失败时必须保留用户填写内容，并明确指出名称、路径、权限或目录冲突中的具体问题。

### 6.3 新建与命名对话

点击“新建对话”后立即进入空对话，不弹出标题表单。

首次发送消息后，模型根据研究目标自动生成简短标题。生成失败时暂用“新对话”；用户可以随时手动修改标题。修改标题不改变消息、产物或公共记忆关联。

新对话自动获得以下项目上下文：

- 当前项目工作区中的可用产物；
- 项目公共记忆的最新版本；
- 全局论文库的检索能力；
- 当前项目的安全和模型配置。

它不会自动继承其他对话的完整消息历史。需要跨对话复用的结论必须先进入项目公共记忆，或由用户显式引用相应产物。

## 7. 研究主流程

| 阶段 | 用户看到什么 | Agent 做什么 | 主要控制点 |
| --- | --- | --- | --- |
| 目标 | 对话输入和项目上下文 | 理解任务类型与最终交付 | 用户自由描述，不要求填写复杂表单 |
| 计划 | 可编辑研究问题、范围、数量和交付形式 | 将目标转为有界执行计划 | 用户确认前不联网、不批量调用模型 |
| 授权 | 联网、论文库写入和模型调用摘要 | 汇总本轮有外部影响的操作 | 同类批次集中确认，取消项不得执行 |
| 论文 | 论文库结果与在线候选、相关性及推荐理由 | 聚合、去重、排序并标记是否已在库中 | Agent 推荐，用户决定最终论文集合 |
| 执行 | 分阶段进度、已完成项和失败项 | 下载缺失论文、索引、精读和生成中间产物 | 可在阶段安全点暂停、取消和恢复 |
| 精读 | 论文结构化解读和原文证据入口 | 提取问题、方法、实验、限制与证据 | 用户可追问任意论文细节或修改精读结论 |
| 对比 | 论文 × 维度矩阵、共识、冲突和空白 | 复用精读证据完成跨论文综合 | 用户可追问单元格或通过对话新增维度 |
| 综述 | 可编辑 Markdown 及证据引用 | 生成有边界的综合结论 | 用户检查、修改并点击“完成” |

### 7.1 阶段不是对话边界

对话在整个研究流程中持续存在。进入后续阶段后，用户仍可询问当前及此前所有阶段的详细信息，例如：

- 在精读阶段追问某篇论文的模型结构、实验设置或证据上下文；
- 在对比阶段追问某篇论文在某个维度上的判断依据；
- 通过对话新增“推理成本”等比较维度，并回填所有入选论文；
- 在综述阶段要求修改研究问题、论文集合、比较结论或章节文本。

### 7.2 修改、版本与下游失效

通过对话修改产物时，系统保存新版本而不是静默覆盖。若修改历史阶段，依赖它的后续产物必须标记为“需要重新生成”。

重新生成前，用户仍可查看旧版本，但旧版本不能继续作为最新成果导出或写入公共记忆。重新生成后必须记录使用的上游版本、论文集合和证据版本。

## 8. 完成与继续研究

综述阶段唯一突出主按钮是“完成”。点击后系统自动：

1. 校验引用、证据状态和必须字段。
2. 将本次对话成果保存为 Markdown 到项目工作区。
3. 把该 Markdown 加入或更新为项目公共记忆。
4. 将当前对话标记为已完成，但保留继续追问和修改能力。
5. 向用户显示保存位置、公共记忆状态和“新建对话”入口。

“完成”不触发浏览器下载弹窗。DOCX 等格式属于次要导出操作，不与“完成”争夺主操作层级。

完成后继续修改当前对话的研究成果时，系统将其标记为未同步修改。用户再次点击“完成”后生成新版本，并更新项目公共记忆。

## 9. 对话式查询与修改规则

Agent 回答阶段问题时必须说明信息来自哪里：论文原文、阶段产物、项目公共记忆、模型推断或联网结果。

| 用户意图 | 产品行为 |
| --- | --- |
| 询问细节 | 回答并提供相关论文、阶段和证据入口 |
| 修改当前阶段 | 创建当前产物新版本，保留旧版本 |
| 修改历史阶段 | 创建历史产物新版本，并标记所有受影响下游产物 |
| 新增比较维度 | 说明所需证据，回填全部入选论文；缺少数据时显式标记未知 |
| 引入新论文 | 先查共享论文库，再去重下载；更新论文集合并使相关下游产物失效 |

用户的自然语言修改指令不能绕过联网、论文库写入、批量模型调用或覆盖公共记忆所需的确认与版本规则。

## 10. 可信度与安全体验

### 10.1 证据要求

每个关键结论必须能展开查看论文、页码或章节、逐字片段和当前证据状态。系统找不到足够证据时必须显示“证据不足”，不能自动补全为确定结论。

比较和综述优先复用已经确认的精读证据。新增维度需要新证据时，应明确触发补充抽取或标记未知。

### 10.2 外部影响确认

以下行为在执行前集中展示影响范围并获得确认：

- 联网检索或抓取网页；
- 向共享论文库下载、替换或重新索引文件；
- 批量模型调用及预计规模；
- 覆盖或更新项目公共记忆；
- 删除论文、项目、对话或产物。

同一次已确认批次中的重复步骤不应逐项打断用户。影响范围变化时必须重新确认。

综述页的“完成”按钮本身就是保存和更新公共记忆的明确确认，点击后直接执行，不再增加第二个确认弹窗。

### 10.3 本地与模型边界

论文 PDF、工作区文件和数据库默认保存在本机。模型只接收完成当前操作所需的问题、计划和选中文本片段，不默认上传完整论文库或项目目录。

## 11. 空状态、失败与恢复

| 状态 | 产品响应 |
| --- | --- |
| 未配置论文库 | 阻止下载和全文研究，引导选择全局论文库文件夹 |
| 论文库为空 | 允许联网发现；说明首批论文将保存到共享库 |
| 命中重复论文 | 复用已有文件和索引，并显示去重依据 |
| 下载或解析失败 | 保留其他成功论文，列出失败项、原因和重试入口 |
| 模型调用失败 | 保留已完成阶段和中间产物，从失败步骤重试 |
| 上游产物被修改 | 下游显示失效原因，不允许把旧结果标为最新公共记忆 |
| 页面关闭或服务重启 | 恢复项目、对话、阶段、确认状态和未完成任务 |
| 公共记忆写入失败 | 当前对话不标记完成，保留草稿并显示路径或权限问题 |

## 12. V1 范围边界

V1 包含本地单用户、多项目、多对话、共享论文库、阶段化研究、证据追溯和项目公共记忆。

以下能力不进入首个 V1 上线范围：

- 多用户实时协作与权限管理；
- 云端项目同步和公共发布；
- 移动端完整编辑体验；
- 自动替用户提交论文或向第三方发送内容；
- 无限制自主运行或绕过用户设定的预算与确认。

## 13. 产品验收场景

### 13.1 项目启动

1. 用户配置共享论文库。
2. 创建项目并选择工作区。
3. 系统自动进入默认对话。
4. 用户首次提问后自动生成标题。
5. 用户可以手动修改标题且不丢失状态。

### 13.2 主题调研到公共记忆

1. 用户描述主题并编辑 Agent 计划。
2. 集中批准联网、下载和模型操作。
3. 从全局论文库和在线结果中确认论文集合。
4. 完成精读、比较和综述，并检查证据。
5. 点击“完成”，Markdown 自动进入工作区和项目公共记忆。

### 13.3 跨阶段修改

1. 用户在对比阶段要求修改论文筛选。
2. 系统保存论文阶段新版本。
3. 对比和综述被标记为需要重新生成。
4. 用户可以查看旧版本但不能将其作为最新成果完成。
5. 重新生成后，新版本继承新的论文集合与证据。

### 13.4 跨对话继续研究

1. 用户完成第一个对话并生成项目公共记忆。
2. 点击“新建对话”后立即进入空对话，不填写标题。
3. 新对话读取项目公共记忆，但不复制旧对话全部消息。
4. 首次提问后自动生成标题。
5. 新成果可以再次通过“完成”加入项目公共记忆。

### 13.5 全局论文去重

1. 两个项目分别发现同一篇论文。
2. 第一个项目授权后将论文下载到共享库。
3. 第二个项目命中 DOI 或其他稳定身份。
4. 系统直接复用已有文件、索引和元数据。
5. 共享论文库中始终只有一份论文文件。
